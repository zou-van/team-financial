## Project overview

This is a static Vite + React dashboard for monthly team financial data. There
is no backend: source Excel workbooks are parsed into bundled data files at
build time.

```text
excel/*.xlsx -> scripts/parse.py -> data/*.md, data/index.json, data/trend.json
                                             -> src/lib/loadData.js -> React UI
```

The UI has two views:

- Monthly detail: metrics are rows and teams are columns with three-level
  grouped headers.
- Trend chart: Recharts lines based on a curated metric list and selectable
  organization level.

## Common commands

| Command | Use |
| --- | --- |
| `npm run dev` | Start the Vite server (port 5173). |
| `npm run build` | Produce and validate the production bundle. |
| `python scripts/parse.py` | Parse every workbook in `excel/` into `data/`. |

`parse.py` requires `openpyxl` and `pyyaml`. After regenerating data, rebuild
or restart the dev server so Vite picks up new Markdown files.

## Data and hierarchy contracts

- The parser reads sheet `差距分析(团队)`: team headers from row 2, data from row
  4, and ignores row 3. It extracts the final six-digit `YYYYMM` in each
  filename.
- `team-mapping.yaml` defines the boss -> leader -> sub-team -> small-team
  hierarchy, the `trend_metrics` whitelist, virtual aggregate columns, and
  aliases for duplicate aggregate names. The parser embeds this mapping in
  `data/index.json` and `data/trend.json`.
- `virtual_aggregates` become active from their `start_month`, are inserted
  after their configured member, and are calculated only when every member is
  numeric. They are display data generated by the parser, not Excel columns.
- `vite.config.js` must retain `assetsInclude: ['**/*.md']`; it enables the
  raw Markdown imports in `src/lib/loadData.js`.
- Excel error values such as `#REF!` and `#DIV/0!` are intentional display data
  and must remain strings.

## Keep duplicate-name logic synchronized

Excel can contain duplicated team names, commonly when a sub-team aggregate
shares a small-team name. The first name is preserved; subsequent names become
`name(2)`, `name(3)`, and so on.

This exact behavior is implemented in both locations below and must be changed
in tandem:

- `scripts/parse.py` (`parse_excel()`)
- `src/lib/loadData.js` (`buildColumnGroups()`)

The aggregate columns returned by `buildColumnGroups()` drive the monthly
table's bold blue styling. Negative values are styled red. The monthly table
also freezes its compact metric column while horizontally scrolling and
supports sub-team/Leader collapse toggles.

## Change discipline

- Make the smallest change that directly serves the request; avoid unrelated
  refactors and formatting churn.
- When a parser or mapping change affects generated files, regenerate the data
  and review the resulting diff.
- Validate UI or data changes with `npm run build`; run the parser when the
  source workbooks or parsing behavior changed.
- Do not delete, regenerate, or stage existing user changes without explicit
  authorization.
