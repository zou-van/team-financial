## 目标

让管理者能快速看懂飞书卡片中的团队风险：哪个团队有风险、由谁负责、触发了什么指标、下一步该做什么。

## 背景

项目已经可以从月度财务数据生成风险榜单和管理洞察。现在先把这条真实需求放入研发 Loop，后续再按 Loop 推进具体改动。

## 验收标准

- [ ] 最多展示 3 个不同的风险团队
- [ ] 每条风险包含负责人
- [ ] 每条风险包含触发风险的指标和数值
- [ ] 每条风险包含下一步行动建议
- [ ] 金额保留“千元”单位
- [ ] LLM 调用失败时仍能生成规则版洞察
- [ ] 正式发送前可以通过 dry-run 预览

## 不做什么

- 不让 LLM 自己决定风险等级
- 不引入图数据库或后端服务
- 不自动正式发送飞书消息
- 不修改 Excel 解析和月度表格展示逻辑

## 实施计划

- [ ] 检查现有洞察生成和卡片展示逻辑
- [ ] 确定需要修改的最小文件范围
