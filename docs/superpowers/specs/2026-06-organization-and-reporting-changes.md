# 2026-06 组织与报表展示变更

日期：2026-06-01（规则生效月）  
状态：已实现

## 目标

在不修改财务 Excel 源结构的前提下，反映 2026 年 6 月起的组织归属和负责人汇总视图，并提升月度表格的可读性与横向浏览体验。

## 组织与展示顺序

组织层级由 `team-mapping.yaml` 维护，展示顺序即数组声明顺序。

### 沈晓华 → 营销中台

```text
Coupon → 多拉 → CRM Portal → 孙伟（汇总） → 企微社群 → 营销中台
```

- CRM Portal 归属沈晓华的营销中台。
- 孙伟负责 Coupon、多拉、CRM Portal 的汇总；企微社群负责人为邹文佐，不纳入孙伟汇总。
- 营销中台整体负责人仍为沈晓华。

### 赵华 → 线上运营

```text
PMS&天气中台 → PH点餐 → K点餐 → 点餐平台 → Prime → 扁鹊&大禹&商城&预约
→ 钱知麟（汇总） → 智能物流 → 接单&运营 → 智能商圈 → 线上运营
```

- 钱知麟汇总 PMS&天气中台、PH点餐、K点餐、点餐平台、Prime、扁鹊&大禹&商城&预约。
- 线上运营整体负责人仍为赵华。

### 重名汇总列

Excel 中小团队与子团队都可能名为“前端创新”。为避免列名歧义，子团队汇总在界面和生成数据中显示为 **前端创新汇总**。

## 计算汇总列规则

- 配置项：`team-mapping.yaml` 的 `virtual_aggregates`。
- 生效时间：仅当 `month_key >= start_month` 时生成；本次两个汇总均从 `2026-06` 起出现，历史月份不回填。
- 位置：紧跟在配置的 `after` 成员之后。
- 值：对成员在同一指标行的原始数值求和；任一成员不是数字时，结果为缺失值，不以零替代。
- 这些是解析时生成的展示列，不要求 Excel 中存在对应列。

## 月度详情交互和格式

- 数值单位为千元；数字使用千分位并最多保留两位小数。
- 指标列和左侧展开按钮列在横向滚动时固定。
- 子团队标题上的 `−` 收起其小团队，只保留子团队汇总列；`+` 恢复。
- 张浩、沈晓华、赵华标题上的 `−` 收起其全部子团队；表格保留一个占位列；`+` 恢复。
- `回款YTD合计` 行可单独展开或收起其明细行。
- 汇总列以加粗/浅色背景区分；负数以红色显示。
- `累计现金流_*` 和 `PMS预计回款（在途）` 的数值可点击查看环比。环比方向由本月
  与上月的数值差判断，比例为 `|本月 - 上月| / |上月|`，精确到两位小数；首月、
  上月缺值或上月为 0 时提示无法计算。

## 趋势图数据契约

趋势图继续使用 `trend_metrics` 白名单。生成 `data/trend.json` 时，解析器为每个月保留当月自己的有序列头，并以“列名 → 值”建立数据；不得使用其他月份的列位置推断值。该规则确保 6 月新增汇总列或组织顺序变化不会导致趋势数据错位。

虚拟汇总列从其生效月份起同样进入趋势数据；趋势图的子团队选择器仍以配置中的实际小团队为成员，展示对应子团队的 Excel 汇总线。

## 飞书通知

状态：**已实现**（`scripts/notify.py`）

### 通知范围

通知范围在独立的 `notification-config.yaml` 中维护，与组织/数据映射分离。该配置
仅定义业务收件人和数据范围，不存储飞书身份、Webhook 或任何密钥。

| 收件人 | 数据范围 |
| --- | --- |
| 朱孝峰 | 赵华团队的全部数据（线上运营） |
| 彭明阳 | 沈晓华 → 营销中台的全部数据；沈晓华 → 大前端 → 自动化营销 |
| 郭一鸣 | 沈晓华 → 大前端 → 大前端-APP；沈晓华 → 前端创新的全部数据 |

- `leader` 范围包含该 Leader 下全部展示列（小团队）。
- `sub_team` 范围包含该子团队的所有小团队。
- `teams` 是对 `sub_team` 的进一步限制，只发送所列小团队。
- 不包含虚拟汇总列（如孙伟（汇总）、钱知麟（汇总）），因为通知脚本自行按小团队
  求和，避免重复计算。

### 消息格式：飞书 Interactive Card 2.0

- 纯文本排版受限，无法展示表格
- 截图方案需要额外的 `im:resource:upload` 授权 scope
- 卡片原生支持结构化布局、指标卡、数据表

### 指标与取值

- `PMS预计回款（在途）`：当前在途回款金额及环比变化（本月 vs 上月）。
- `累计现金流`：从当前月份所有 `累计现金流_*` 指标中取日期最新的一条；展示金额、
  正负状态、环比变化（本月 vs 上月）。
- `7月现金流预估`：取自 `7月现金流预估` 行，结合当前现金流状态标注”预计转正”
  /”仍承压”/”持续为正”。
- `回款目标（考虑2倍奖金）`：展示该范围的奖金目标金额。
- `考虑2倍奖金在途回款差距（+超额/-落后）`：仅当数值为负时，触发新订单缺口提醒
  和出单截止建议。

### 团队明细拆解

每个 scope 独立展示。当 scope 的团队集合与 `team-mapping.yaml` 中的
`virtual_aggregates` 存在交集时，在该 scope 下展示二级明细表：
- virtual_aggregate 所定义的汇总组（如 钱知麟（汇总）= 6 个小团队）
- 不在任何 virtual_aggregate 内的剩余团队各自独立列出

无 virtual_aggregate 覆盖的 scope 不展示二级明细表。

### 出单截止建议

当存在新订单缺口时，按数据年份生成截止日期：`YYYY-10-15`。文案说明：订单从出单到
实际回款需要较长周期，在 10 月 15 日前完成新订单出单才能为当年回款和奖金目标留出
回款时间；这不是奖金目标的会计截止日。

### 发送通道：lark-cli

通知发送固定使用 `lark-cli`，不使用浏览器 Webhook 或前端请求：

1. 通讯录解析收件人：
   ```bash
   lark-cli contact +search-user \
     --queries “朱孝峰,彭明阳,郭一鸣” \
     --exclude-external-users --format json --as user
   ```

2. 生成卡片 JSON（`scripts/notify.py`），先发给自己 `--dry-run` 预览。
3. 确认后发送私聊卡片：
   ```bash
   lark-cli im +messages-send \
     --user-id <open_id> --msg-type interactive --content '<card_json>' \
     --as user --idempotency-key “team-financial-YYYY-MM-<recipient>”
   ```

- 以授权用户身份发送（`--as user`）。
- 幂等键格式：`team-financial-YYYY-MM-<recipient>`，防止重复发送。
- 发送前必须先预览；通讯录解析失败、授权失效、网络异常时不发送。
- 需要的用户授权 scope：`contact:user:search`、`im:message`。
- 卡片 JSON 不得手写或复制，必须通过 `scripts/notify.py` 生成。
